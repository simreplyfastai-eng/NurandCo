STRIPE PAYMENT FLOW — FULL IMPLEMENTATION
━━━━━━━━━━━━━━━━━━━━━━━━
When a client clicks "Book Now" on the 
website and fills in the booking form, 
the final step is Stripe payment.

STEP 1 — BOOKING SUMMARY BEFORE PAYMENT:
Before showing the Stripe payment form, 
show a clean summary screen:

"Confirm Your Booking

Treatment: [treatment name]
Date: [Tuesday, 15 April 2026]
Time: [14:00]
Duration: approximately [X] minutes

Deposit to pay now: £[50% of price]
Balance due on arrival: £[remaining 50%]

Pay securely with card ↓"

Then show the Stripe payment form 
embedded below the summary.

STEP 2 — STRIPE PAYMENT INTENT:
When the client reaches the payment step:
POST /api/stripe/create-payment-intent
Body: { 
  amount: [deposit in pence], 
  treatment: [name],
  clientName: [name],
  clientEmail: [email]
}

Backend creates a Stripe PaymentIntent 
for the deposit amount (50% of treatment 
price, in pence).
Returns { clientSecret } to the frontend.

Frontend uses Stripe.js to mount the 
payment element:
const stripe = Stripe(STRIPE_PUBLISHABLE_KEY)
const elements = stripe.elements({ 
  clientSecret 
})
Mount the payment element to a div 
#stripe-payment-element
Style it to match the site — white 
background, gold accent #C9A96E

STEP 3 — ON PAYMENT SUCCESS:
When stripe.confirmPayment() resolves 
successfully:
- POST /api/bookings with all booking 
  data plus stripePaymentIntentId
- Save booking to PostgreSQL with:
  depositPaid: true
  status: "Confirmed"
  stripePaymentIntentId: [id]
- Send client confirmation email
- Send admin notification email
- Show success screen (see below)

STEP 4 — SUCCESS SCREEN:
Show immediately after payment confirmed:

Gold checkmark icon, large, centred.

"Booking Confirmed! 

Treatment: [treatment name]
Date: [Tuesday, 15 April 2026]  
Time: [14:00]
Duration: approximately [X] minutes

Deposit paid: £[amount] ✓
Balance due on arrival: £[amount]

A confirmation has been sent to 
[client email]

See you soon!
Questions? Contact us:
Instagram: @dermadollaesthetics
WhatsApp: [number from settings]"

"Deposit paid: £X ✓" — green text
"Balance due on arrival: £X" — black text
Single "Done" button closes the modal.
No auto-close.

STEP 5 — PAYMENT FAILURE HANDLING:
If stripe.confirmPayment() fails:
- Do NOT create a booking
- Show error message below the 
  payment form in red:
  "Payment failed: [Stripe error message]
  Please check your card details and 
  try again."
- Keep the form open so they can retry
- Do not close the modal

If the network fails after payment 
succeeds but before POST /api/bookings:
- The Stripe webhook (see below) will 
  catch this and create the booking
- Show success screen anyway since 
  money was taken

STEP 6 — STRIPE WEBHOOK:
POST /api/stripe/webhook handles 
payment_intent.succeeded events.

On this event:
1. Find if a booking already exists 
   with this stripePaymentIntentId
2. If yes: ensure depositPaid: true 
   and status: "Confirmed" — idempotent
3. If no booking exists yet (network 
   failure edge case):
   - Create the booking from the 
     PaymentIntent metadata
   - Set depositPaid: true, 
     status: "Confirmed"
   - Send confirmation email to client
   - Send notification to admin

Store Stripe webhook secret as 
STRIPE_WEBHOOK_SECRET in Replit Secrets.
Verify webhook signature on every 
incoming event using:
stripe.webhooks.constructEvent(
  body, signature, STRIPE_WEBHOOK_SECRET
)
Return 400 if signature invalid.
Return 200 immediately to acknowledge.

DEPOSIT LOGIC THROUGHOUT
━━━━━━━━━━━━━━━━━━━━━━━━
Deposit is always exactly 50% of the 
treatment price, rounded down to the 
nearest pound.
deposit = Math.floor(price / 2)
balance = price - deposit

This must be consistent across:
- The booking summary screen
- The Stripe PaymentIntent amount 
  (in pence: deposit * 100)
- The success screen
- The confirmation email
- The portal booking record
- The Finance deposits collected figure

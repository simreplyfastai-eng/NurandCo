PART 1 — NO DOUBLE BOOKINGS
===============================================================

In the booking creation logic (both customer-facing 
POST /api/bookings AND the Stripe webhook handler),
add this check BEFORE inserting any booking:

async function isSlotAvailable(
  locationId, bookingDate, timeSlot
) {
  const { data } = await supabaseAdmin
    .from('bookings')
    .select('id')
    .eq('location_id', locationId)
    .eq('booking_date', bookingDate)
    .eq('time_slot', timeSlot)
    .not('status', 'eq', 'cancelled')
    .limit(1)
  
  return !data || data.length === 0
}

If slot is NOT available → return 409:
{
  error: 'Sorry, this slot has just been taken.',
  code: 'SLOT_TAKEN'
}

On the frontend booking widget:
  If the API returns SLOT_TAKEN:
  Show a clear message:
  "This time slot has just been booked by 
  someone else. Please choose another time."
  Refresh the available slots automatically
  so the calendar updates immediately.

Also check date is not blocked:
async function isDateBlocked(locationId, date) {
  const { data } = await supabaseAdmin
    .from('blocked_dates')
    .select('id')
    .eq('location_id', locationId)
    .eq('date', date)
    .limit(1)
  
  return data && data.length > 0
}

If date is blocked → return 409:
{ error: 'This date is not available.', 
  code: 'DATE_BLOCKED' }

Also check location is open that day:
async function isLocationOpen(locationId, date) {
  const dayOfWeek = new Date(date).getDay()
  const adjustedDay = dayOfWeek === 0 ? 6 : dayOfWeek - 1
  
  const { data } = await supabaseAdmin
    .from('availability_settings')
    .select('is_open, open_time, close_time')
    .eq('location_id', locationId)
    .eq('day_of_week', adjustedDay)
    .single()
  
  if (!data || !data.is_open) return false
  return true
}

If location closed → return 409:
{ error: 'The clinic is closed on this day.',
  code: 'CLINIC_CLOSED' }

Run ALL three checks before creating any booking.
Order: date blocked → clinic closed → slot taken.

PART 2 — SMART CLIENT UPSERT (NO DUPLICATES)
===============================================================

When a booking is confirmed (via Stripe webhook 
or admin portal), find or create the client.

NEVER create a duplicate client record.
A client is identified by:
  email + location_id (primary)
  OR phone + location_id (secondary fallback)

Use this upsert logic:

async function findOrCreateClient(
  locationId, clientData
) {
  const { name, email, phone } = clientData
  
  // 1. Try to find by email first (most reliable)
  if (email) {
    const { data: existing } = await supabaseAdmin
      .from('clients')
      .select('*')
      .eq('location_id', locationId)
      .ilike('email', email.trim())
      .single()
    
    if (existing) {
      // Client exists — UPDATE their record
      const { data: updated } = await supabaseAdmin
        .from('clients')
        .update({
          // Update name if we have a better version
          name: name || existing.name,
          // Update phone if missing
          phone: phone || existing.phone,
          // Increment visit count
          visit_count: (existing.visit_count || 0) + 1,
          // Update last visit to today
          last_visit: new Date().toISOString().split('T')[0]
        })
        .eq('id', existing.id)
        .select()
        .single()
      
      return updated
    }
  }
  
  // 2. Try to find by phone if email not found
  if (phone) {
    const cleanPhone = phone.replace(/\s+/g, '')
      .replace(/^\+44/, '0')
    
    const { data: existingByPhone } = await supabaseAdmin
      .from('clients')
      .select('*')
      .eq('location_id', locationId)
      .or(`phone.eq.${phone},phone.eq.${cleanPhone}`)
      .single()
    
    if (existingByPhone) {
      // Found by phone — update email if we have it
      const { data: updated } = await supabaseAdmin
        .from('clients')
        .update({
          email: email || existingByPhone.email,
          name: name || existingByPhone.name,
          visit_count: (existingByPhone.visit_count || 0) + 1,
          last_visit: new Date().toISOString().split('T')[0]
        })
        .eq('id', existingByPhone.id)
        .select()
        .single()
      
      return updated
    }
  }
  
  // 3. Client is genuinely new — INSERT
  const { data: newClient } = await supabaseAdmin
    .from('clients')
    .insert({
      location_id: locationId,
      name: name || 'Unknown',
      email: email || null,
      phone: phone || null,
      visit_count: 1,
      last_visit: new Date().toISOString().split('T')[0],
      total_spent: 0,
      source: 'Website'
    })
    .select()
    .single()
  
  return newClient
}

Call this function EVERY time a booking is 
confirmed — never insert a client directly.

After finding/creating the client:
  Update the booking with the client_id:
  
  await supabaseAdmin
    .from('bookings')
    .update({ client_id: client.id })
    .eq('id', bookingId)

Also update total_spent when booking is complete:
  await supabaseAdmin
    .from('clients')
    .update({
      total_spent: supabase.rpc('increment', {
        row_id: client.id,
        amount: depositAmount
      })
    })
    .eq('id', client.id)

Or simpler — just fetch current total_spent 
and add to it:
  const newTotal = (client.total_spent || 0) + 
    depositAmount
  
  await supabaseAdmin
    .from('clients')
    .update({ total_spent: newTotal })
    .eq('id', client.id)

PART 3 — DATABASE UNIQUE CONSTRAINT
===============================================================

Add a unique constraint to prevent duplicate 
clients at the database level as a safety net.

Run this in Supabase SQL editor:

CREATE UNIQUE INDEX IF NOT EXISTS 
  clients_location_email_unique 
  ON clients(location_id, LOWER(email))
  WHERE email IS NOT NULL;

This means even if the code somehow tries to 
insert a duplicate, Supabase will reject it.

On conflict (duplicate email for same location):
  The upsert in code handles it above, but add 
  a conflict handler as backup:
  
  .from('clients')
  .upsert(clientData, { 
    onConflict: 'location_id,email',
    ignoreDuplicates: false 
  })

CRITICAL — TIMEZONE RULES (NON-NEGOTIABLE)
===============================================================

ALL dates and times in this entire system must 
use UTC/GMT. No local timezone conversions. Ever.

RULE 1 — Date parsing:
  NEVER use: new Date('2026-04-23')
  This parses as midnight UTC then converts to 
  local time, causing off-by-one date bugs.
  
  ALWAYS use: new Date('2026-04-23T00:00:00Z')
  Or: new Date('2026-04-23T00:00:00.000Z')
  This forces UTC midnight, no timezone shift.

RULE 2 — Day of week:
  NEVER use: date.getDay()
  This returns day in LOCAL timezone.
  
  ALWAYS use: date.getUTCDay()
  Returns: 0=Sun, 1=Mon, 2=Tue, 3=Wed, 
           4=Thu, 5=Fri, 6=Sat
  
  Example that caused the Dermadoll bug:
    new Date('2026-04-17').getDay() 
    → could return 3 (Wed) in UTC+1
    BUT the date is actually Thursday Apr 17
    
    new Date('2026-04-17T00:00:00Z').getUTCDay()
    → returns 4 (Thu) ✓ CORRECT

RULE 3 — Storing dates in Supabase:
  Booking date → store as DATE type (YYYY-MM-DD)
  Booking time → store as TIME type (HH:MM:SS)
  Both in UTC/GMT. No timezone offset.
  
  When inserting: 
    booking_date: '2026-04-23'  (plain date string)
    time_slot: '14:00'          (plain time string)
  
  NEVER store a full ISO datetime for booking_date
  as this causes the timezone shift bug.

RULE 4 — Time slot generation:
  Generate slots using plain string arithmetic
  NOT Date objects:
  
  function generateSlots(openTime, closeTime, 
    durationMins) {
    const slots = []
    let [h, m] = openTime.split(':').map(Number)
    const [closeH, closeM] = closeTime.split(':')
      .map(Number)
    
    while (h < closeH || (h === closeH && m < closeM)) {
      slots.push(
        `${String(h).padStart(2,'0')}:${String(m).padStart(2,'0')}`
      )
      m += durationMins
      if (m >= 60) { h += Math.floor(m/60); m = m%60 }
    }
    return slots
  }
  
  This generates "10:00", "10:30"... with NO 
  timezone involvement whatsoever.

RULE 5 — Displaying dates to the customer:
  When showing "Thursday 23 April 2026":
  
  function formatDate(dateStr) {
    // dateStr = '2026-04-23'
    const [y, m, d] = dateStr.split('-').map(Number)
    const date = new Date(Date.UTC(y, m-1, d))
    return date.toLocaleDateString('en-GB', {
      weekday: 'long',
      day: 'numeric', 
      month: 'long',
      year: 'numeric',
      timeZone: 'Europe/London'
    })
  }
  
  Always pass timeZone: 'Europe/London' to 
  display functions so UK clients see correct 
  dates regardless of server timezone.

RULE 6 — Stripe metadata:
  Store booking_date as 'YYYY-MM-DD' string
  Store booking_time as 'HH:MM' string
  Extract from metadata with no conversion:
  
  const bookingDate = metadata.bookingDate  // '2026-04-23'
  const timeSlot = metadata.bookingTime     // '14:00'
  
  Insert directly to Supabase without parsing

RULE 7 — "Is this slot in the past?" check:
  If date is today, remove past slots:

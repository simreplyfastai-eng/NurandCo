FIX 3 — bootPortal ON PAGE LOAD
===============================================================

Find the init / DOMContentLoaded function.
Replace its body entirely with:

  async function bootPortal() {
    const token = localStorage.getItem('portal_token')
    const locId = localStorage.getItem('portal_location_id')
    const locName = localStorage.getItem('portal_location_name')

    if (!token) {
      showPage('login-page')
      return
    }

    try {
      const r = await fetch('/api/auth/verify', {
        headers: { 'Authorization': 'Bearer ' + token }
      })
      if (!r.ok) throw new Error('invalid')
    } catch(e) {
      localStorage.clear()
      showPage('login-page')
      return
    }

    window._SESSION_TOKEN = token

    if (locId) {
      window._SESSION_LOC_ID = locId
      window._SESSION_LOC_NAME = locName
      showPage('portal')
      loadDashboard()
    } else {
      showPage('location-selector')
    }
  }

  document.addEventListener('DOMContentLoaded', bootPortal)

Note: use whatever showPage() equivalent 
already exists in the code — the function 
that hides all sections and shows one.

===============================================================
FIX 4 — authFetch READS FROM localStorage
===============================================================

Find the authFetch function. Replace with:

  function authFetch(url, opts = {}) {
    const token = window._SESSION_TOKEN ||
                  localStorage.getItem('portal_token')
    const locId = window._SESSION_LOC_ID ||
                  localStorage.getItem('portal_location_id')
    return fetch(url, {
      ...opts,
      headers: {
        'Content-Type': 'application/json',
        ...opts.headers,
        'Authorization': 'Bearer ' + (token || ''),
        'X-Location-Id': locId || ''
      }
    })
  }

FIX 5 — LOGIN HANDLER: NO DOUBLE SHOW
===============================================================

Find the login form submit handler.
Replace entirely with:

  async function handleLogin(email, password) {
    try {
      const r = await fetch('/api/auth/login', {
        method: 'POST',
        headers: {'Content-Type': 'application/json'},
        body: JSON.stringify({ email, password })
      })
      if (!r.ok) {
        showLoginError('Incorrect email or password')
        return
      }
      const { token } = await r.json()
      localStorage.setItem('portal_token', token)
      window._SESSION_TOKEN = token
      showPage('location-selector')
      loadLocations()
    } catch(e) {
      showLoginError('Login failed, please try again')
    }
  }

CRITICAL: After login succeeds NEVER call
bootPortal(), init(), or showPage('login-page')
again until the user clicks SIGN OUT.

FIX 10 — AVAILABILITY SPECIFICALLY
===============================================================

The availability SAVE CHANGES fails with 
"Failed to save". Two reasons:

A) The POST uses plain fetch() not authFetch()
   Fix: change to authFetch()

B) The response handler checks for error 
   but the Supabase upsert returns an error 
   due to missing unique constraint.

Add this to Supabase (run in SQL editor):
  ALTER TABLE availability_settings 
  ADD CONSTRAINT IF NOT EXISTS 
  avail_loc_day_unique 
  UNIQUE (location_id, day_of_week);

And fix the upsert in the POST handler:
  const { error } = await supabaseAdmin
    .from('availability_settings')
    .upsert({
      location_id: locationId,
      day_of_week: day.day_of_week,
      is_open: day.is_open,
      open_time: day.open_time,
      close_time: day.close_time
    }, { onConflict: 'location_id,day_of_week' })

  if (error) {
    console.error('availability save error:', error)
    return res.status(500).json({ error: error.message })
  }

Also fix time format — Supabase returns 
"09:00:00" but portal expects "09:00":

  close_time: row.close_time?.slice(0,5)

BUG 2 — TREATMENTS EDIT BUTTON DOES NOTHING
===============================================================

Clicking the pencil edit icon on any treatment 
row in the admin portal does nothing.

THE FIX:
Use event delegation — bind ONE listener to the 
treatments container, not individual buttons:

  document.querySelector('#treatments-container')
    ?.addEventListener('click', e => {
      const btn = e.target.closest('[data-action]')
      if (!btn) return
      const action = btn.dataset.action
      const row = btn.closest('[data-treatment-id]')
      const id = row?.dataset.treatmentId
      if (action === 'edit') openEditRow(row, id)
      if (action === 'delete') deleteRow(row, id)
      if (action === 'save-edit') saveRow(row, id)
      if (action === 'cancel-edit') cancelEdit(row)
    })

Each treatment row must have:
  data-treatment-id="[supabase uuid]"
  data-name="[name]"
  data-price="[price]"
  data-duration="[mins]"
  data-category="[category]"

openEditRow converts cells to inputs pre-filled 
with current values. Save calls PUT /api/treatments/:id.
On success re-renders the row read-only.
Cancel restores original values.

+ ADD per category calls POST /api/treatments.
New treatment immediately appears in list AND 
on the customer booking page on next load.

SAVE CHANGES (top button) batch-saves all 
rows currently in edit mode.

  const token = localStorage.getItem('portal_token')

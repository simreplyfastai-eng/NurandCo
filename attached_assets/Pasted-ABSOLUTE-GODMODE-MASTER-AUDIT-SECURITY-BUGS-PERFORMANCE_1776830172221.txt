STEP 7 — RATE LIMITING

Add rate limiting to prevent brute force 
and abuse. Install if not present:
  npm install express-rate-limit

Apply limits:

  import rateLimit from 'express-rate-limit'

  // Login: 10 attempts per 15 mins
  const loginLimiter = rateLimit({
    windowMs: 15 * 60 * 1000,
    max: 10,
    message: { error: 'Too many login 
      attempts, try again in 15 minutes' }
  })
  app.use('/api/auth/login', loginLimiter)

  // General API: 100 req per minute
  const apiLimiter = rateLimit({
    windowMs: 60 * 1000,
    max: 100
  })
  app.use('/api/', apiLimiter)

  // Booking creation: 5 per hour per IP
  const bookingLimiter = rateLimit({
    windowMs: 60 * 60 * 1000,
    max: 5
  })
  app.use('/api/bookings/create', 
    bookingLimiter)

STEP 11 — SUPABASE ROW LEVEL SECURITY

Check RLS is enabled on sensitive tables.
Run in Supabase SQL:

  -- Check RLS status
  SELECT tablename, rowsecurity 
  FROM pg_tables 
  WHERE schemaname = 'public'
  ORDER BY tablename;

  -- Enable RLS on all tables
  ALTER TABLE bookings ENABLE ROW 
    LEVEL SECURITY;
  ALTER TABLE clients ENABLE ROW 
    LEVEL SECURITY;
  ALTER TABLE medical_forms ENABLE ROW 
    LEVEL SECURITY;
  ALTER TABLE consent_forms ENABLE ROW 
    LEVEL SECURITY;
  ALTER TABLE payments ENABLE ROW 
    LEVEL SECURITY;

  -- Service role bypasses RLS 
  -- (server always uses service role)
  -- Anon role gets nothing:
  CREATE POLICY "deny_anon" ON bookings
    FOR ALL TO anon USING (false);
  CREATE POLICY "deny_anon" ON clients
    FOR ALL TO anon USING (false);
  CREATE POLICY "deny_anon" ON medical_forms
    FOR ALL TO anon USING (false);
  CREATE POLICY "deny_anon" ON consent_forms
    FOR ALL TO anon USING (false);
  CREATE POLICY "deny_anon" ON payments
    FOR ALL TO anon USING (false);

This means even if someone gets the anon 
key they can read zero data.

    {12}$/i

    .from('bookings').select('id,

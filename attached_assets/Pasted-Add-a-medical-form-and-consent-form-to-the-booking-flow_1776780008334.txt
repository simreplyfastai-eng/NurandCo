Add a medical form and consent form to the booking 
flow. After Stripe payment completes, redirect the 
client to complete both forms before showing 
confirmation. Build this as a reusable module.

===============================================================
STEP 1 — ADD TABLES TO SUPABASE
===============================================================

Run this SQL in the Supabase SQL editor first:

CREATE TABLE IF NOT EXISTS medical_forms (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  location_id UUID REFERENCES locations(id) NOT NULL,
  booking_id UUID REFERENCES bookings(id) NOT NULL,
  client_name TEXT NOT NULL,
  client_email TEXT NOT NULL,
  date_of_birth DATE,
  phone TEXT,
  address TEXT,
  emergency_contact_name TEXT,
  emergency_contact_phone TEXT,
  gp_name TEXT,
  gp_address TEXT,
  is_pregnant BOOLEAN DEFAULT false,
  is_breastfeeding BOOLEAN DEFAULT false,
  allergies TEXT,
  skin_conditions TEXT,
  medical_conditions TEXT,
  medications TEXT,
  previous_aesthetics TEXT,
  previous_reactions TEXT,
  declaration_confirmed BOOLEAN DEFAULT false,
  ip_address TEXT,
  submitted_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS consent_forms (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  location_id UUID REFERENCES locations(id) NOT NULL,
  booking_id UUID REFERENCES bookings(id) NOT NULL,
  client_name TEXT NOT NULL,
  client_email TEXT NOT NULL,
  treatment_name TEXT NOT NULL,
  treatment_date DATE NOT NULL,
  consent_procedure BOOLEAN DEFAULT false,
  consent_risks BOOLEAN DEFAULT false,
  consent_aftercare BOOLEAN DEFAULT false,
  consent_no_guarantee BOOLEAN DEFAULT false,
  consent_over_18 BOOLEAN DEFAULT false,
  consent_medical_accurate BOOLEAN DEFAULT false,
  signature_data TEXT,
  signature_name TEXT,
  ip_address TEXT,
  submitted_at TIMESTAMPTZ DEFAULT NOW()
);

ALTER TABLE medical_forms ENABLE ROW LEVEL SECURITY;
ALTER TABLE consent_forms ENABLE ROW LEVEL SECURITY;

CREATE POLICY "medical_insert" ON medical_forms
  FOR INSERT WITH CHECK (true);
CREATE POLICY "medical_service" ON medical_forms
  FOR ALL USING (auth.role() = 'service_role');
CREATE POLICY "consent_insert" ON consent_forms
  FOR INSERT WITH CHECK (true);
CREATE POLICY "consent_service" ON consent_forms
  FOR ALL USING (auth.role() = 'service_role');

CREATE INDEX IF NOT EXISTS idx_medical_booking
  ON medical_forms(booking_id);
CREATE INDEX IF NOT EXISTS idx_consent_booking
  ON consent_forms(booking_id);
CREATE INDEX IF NOT EXISTS idx_medical_email
  ON medical_forms(client_email, location_id);

===============================================================
STEP 2 — REDIRECT AFTER STRIPE PAYMENT
===============================================================

Find the Stripe payment success handler.
This is wherever the booking is confirmed after payment.

After booking is created/confirmed in the DB,
instead of redirecting to a confirmation page,
redirect to:

  /forms?booking=[bookingId]

Pass the bookingId as a query parameter.
This page is public — no login required.
Validate the bookingId exists in the DB.
If invalid bookingId: redirect to homepage.

===============================================================
STEP 3 — FORMS PAGE LOGIC
===============================================================

The /forms page handles both forms in sequence:

On load:
  1. Fetch booking details using bookingId param
  2. Check if medical_forms record exists for this 
     client_email + location_id
  3. Check if consent_forms record exists for 
     this booking_id

  Decision logic:
  
  IF medical form NOT on file:
    Show STEP 1 (Medical Form) first
    After submit → show STEP 2 (Consent Form)
    After submit → redirect to /confirmed?booking=[id]
  
  IF medical form already on file (returning client):
    Show a brief screen:
    "Welcome back! We have your medical 
    details on file."
    "Has anything changed since your last visit?"
    [Nothing has changed] → skip to consent form
    [Update my details] → show medical form
    After medical or skip → show consent form
    After consent → redirect to /confirmed?booking=[id]
  
  IF both forms already completed:
    Redirect straight to /confirmed?booking=[id]
    (prevents duplicate submissions)

Show a simple step indicator at top:
  Step 1: Medical Form
  Step 2: Consent Form
  Step 3: Confirmed
  Active step highlighted in brand colour.

    const canvas = document.getElementById('sig');
    const ctx = canvas.getContext('2d');
    let drawing = false;
    
    canvas.addEventListener('mousedown', e => {
      drawing = true;
      ctx.beginPath();
      ctx.moveTo(e.offsetX, e.offsetY);
    });
    canvas.addEventListener('mousemove', e => {
      if (!drawing) return;
      ctx.lineTo(e.offsetX, e.offsetY);
      ctx.stroke();
    });
    canvas.addEventListener('mouseup', () => drawing = false);
    canvas.addEventListener('touchstart', e => {
      drawing = true;
      const t = e.touches[0];
      const r = canvas.getBoundingClientRect();
      ctx.beginPath();
      ctx.moveTo(t.clientX - r.left, t.clientY - r.top);
      e.preventDefault();
    }, { passive: false });
    canvas.addEventListener('touchmove', e => {
      if (!drawing) return;
      const t = e.touches[0];
      const r = canvas.getBoundingClientRect();
      ctx.lineTo(t.clientX - r.left, t.clientY - r.top);
      ctx.stroke();
      e.preventDefault();
    }, { passive: false });
    canvas.addEventListener('touchend', () => drawing = false);
    
    ctx.strokeStyle = '#1a1a1a';
    ctx.lineWidth = 1.5;
    ctx.lineCap = 'round';

===============================================================
STEP 7 — API ENDPOINTS
===============================================================

POST /api/forms/medical
  Public — no auth required
  Validate bookingId exists
  Check client not already on file for this location:
    If existing: UPDATE the record
    If new: INSERT new record
  Capture req.ip as ip_address
  Return: { success: true }

POST /api/forms/consent
  Public — no auth required
  Validate bookingId exists
  Validate not already submitted for this booking
  Capture req.ip as ip_address
  Update booking status to 'confirmed' in bookings table
  Send confirmation email via Resend
  Return: { success: true }

GET /api/forms/status?booking=[id]
  Public
  Returns:
    booking details (name, treatment, date, time)
    medical_form: exists true/false
    consent_form: exists true/false
  Used by /forms page on load

GET /api/admin/forms?booking=[id]
  Protected — admin session required
  Returns both forms for a booking
  Including signature_data as base64 PNG

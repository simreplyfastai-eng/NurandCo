ABSOLUTE GODMODE FIX — ROOT CAUSE OF ALL BUGS.

Every single portal bug (double login, saves 
failing, availability not saving, bookings 
not saving, settings not saving) has ONE 
root cause:

THE TOKEN IS NOT BEING STORED IN localStorage.

After login, localStorage is completely empty.
portal_token = null
portal_location_id = null

This means:
  - Every page refresh shows login again
  - Every authFetch() call sends no token
  - Every POST/PUT returns 401 Unauthorized
  - Nothing saves to Supabase

READ portal.html FULLY before touching 
anything. Then make ONLY these changes.

FIX 3 — READ FROM localStorage ON PAGE LOAD
===============================================================

Find the init function or DOMContentLoaded 
handler. Replace its entire contents with:

  async function bootPortal() {
    // Read from localStorage first
    const token = localStorage.getItem('portal_token')
    const locId = localStorage.getItem('portal_location_id')
    const locName = localStorage.getItem('portal_location_name')
    
    if (!token) {
      // No token — show login, stop here
      showPage('login-page')
      return
    }
    
    // Verify token is still valid
    try {
      const r = await fetch('/api/auth/verify', {
        headers: { 'Authorization': 'Bearer ' + token }
      })
      if (!r.ok) throw new Error('invalid')
    } catch(e) {
      // Token invalid — clear and show login
      localStorage.clear()
      showPage('login-page')
      return
    }
    
    // Token valid — restore session
    window._SESSION_TOKEN = token
    
    if (locId) {
      // Location already chosen — go to dashboard
      window._SESSION_LOC_ID = locId
      window._SESSION_LOC_NAME = locName
      showPage('portal')
      loadDashboard()
    } else {
      // No location chosen yet
      showPage('location-selector')
    }
  }

  // Replace whatever calls init on load with:
  document.addEventListener('DOMContentLoaded', bootPortal)
  // OR if it already uses DOMContentLoaded:
  // just replace the function body

Note: showPage() hides all pages and shows 
the specified one. Find how pages are shown 
in the existing code and use the same method.
The pages are: 'login-page', 
'location-selector', 'portal'

FIX 4 — authFetch READS FROM localStorage
===============================================================

Find the authFetch function. Change it to:

  function authFetch(url, opts = {}) {
    const token = window._SESSION_TOKEN || 
                  localStorage.getItem('portal_token')
    const locId = window._SESSION_LOC_ID || 
                  localStorage.getItem('portal_location_id')
    
    return fetch(url, {
      ...opts,
      headers: {
        'Content-Type': 'application/json',
        ...opts.headers,
        'Authorization': 'Bearer ' + (token || ''),
        'X-Location-Id': locId || ''
      }
    })
  }

FIX 5 — LOGIN FLOW: NO DOUBLE SHOW
===============================================================

Find the login form submit handler.
Replace entirely with:

  async function handleLogin(email, password) {
    try {
      const r = await fetch('/api/auth/login', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ email, password })
      })
      
      if (!r.ok) {
        showLoginError('Incorrect email or password')
        return
      }
      
      const { token } = await r.json()
      
      // Store FIRST before doing anything else
      localStorage.setItem('portal_token', token)
      window._SESSION_TOKEN = token
      
      // Then show location selector — ONCE
      // NEVER call bootPortal() or init() here
      showPage('location-selector')
      loadLocations()
      
    } catch(e) {
      showLoginError('Login failed, please try again')
    }
  }

DATA ARCHITECTURE
━━━━━━━━━━━━━━━━━━━━━━━━
All booking and financial data must be stored in 
Replit's built-in key-value database (not localStorage) 
so data persists across devices and sessions for all 
users of the portal.

Use the Replit DB client on the backend:
import Database from "@replit/database"
const db = new Database()

Create a REST API in the Replit backend with these 
endpoints:

GET  /api/bookings         — get all bookings
POST /api/bookings         — create new booking
PUT  /api/bookings/:id     — update booking (status, 
                             payment etc)
DELETE /api/bookings/:id   — delete booking
GET  /api/bookings/date/:date — get bookings for 
                               a specific date
GET  /api/finance/summary  — get revenue totals, 
                             deposits, outstanding
GET  /api/finance/monthly  — get day-by-day revenue 
                             for chart

BOOKING DATA STRUCTURE:
Each booking object saved to DB:
{
  id: unique string (Date.now() + random),
  clientName: string,
  clientEmail: string,
  treatment: string,
  category: string,
  price: number,
  deposit: number,        // always 50% of price
  depositPaid: boolean,   // false until Stripe confirms
  balancePaid: boolean,   // false until marked paid
  date: "YYYY-MM-DD",
  time: "HH:MM",
  status: "Pending" | "Confirmed" | "Complete" | 
          "Cancelled",
  paymentMethod: "Stripe",
  stripePaymentId: null,  // populated when Stripe live
  notes: string,
  createdAt: timestamp,
  source: "Website" | "Portal"
}

FINANCE PAGE — FULLY CONNECTED
━━━━━━━━━━━━━━━━━━━━━━━━
All finance data fetched from API — never hardcoded.

On Finance page load:
1. Fetch GET /api/finance/summary?month=YYYY-MM
   Returns:
   {
     totalRevenue: number,    // sum of all booking 
                              // prices this month
     depositsCollected: number, // sum of deposits 
                                // where depositPaid:true
     balanceOutstanding: number // totalRevenue minus 
                                // depositsCollected
   }
   Populate the 3 summary cards.

2. Fetch GET /api/finance/monthly?month=YYYY-MM
   Returns array of { day: number, cumulative: number }
   for each day of the month.
   Use this to draw the revenue chart.

3. Fetch GET /api/bookings?month=YYYY-MM
   Returns all bookings for the month.
   Populate the transactions table.

When month selector changes:
Re-fetch all three endpoints with new month and 
update all sections simultaneously.

Mark Paid button:
PUT /api/bookings/:id { balancePaid: true }
Recalculate and refresh summary cards instantly.

DASHBOARD — FULLY CONNECTED
━━━━━━━━━━━━━━━━━━━━━━━━
All dashboard KPI cards fetch from API on load:

Revenue This Month:
GET /api/finance/summary?month=current
→ totalRevenue value

Appointments:
GET /api/bookings?month=current
→ count of all bookings

Active Clients:
GET /api/bookings
→ count of unique clientName values

Avg Spend:
totalRevenue / total booking count

Recent Bookings table:
GET /api/bookings?limit=5&sort=newest
→ last 5 bookings across all time

Recent Activity feed:
GET /api/bookings?limit=10&sort=newest
→ derive activity events from booking 
  status and createdAt timestamps

Revenue by Treatment chart:
GET /api/bookings
→ group by category, sum prices
→ render bars proportionally

Today's Schedule:
GET /api/bookings/date/TODAY
→ show all bookings for today sorted by time

All dashboard data refreshes every 60 seconds 
automatically via setInterval.

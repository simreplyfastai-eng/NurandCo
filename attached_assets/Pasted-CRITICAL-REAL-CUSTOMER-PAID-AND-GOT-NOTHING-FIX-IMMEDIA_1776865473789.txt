PROBLEM 2 — RLS BLOCKING FORMS PAGE

We just enabled Row Level Security on the 
bookings table with deny_anon policy.

This means the /forms page can't read the 
booking to pre-fill the form — it gets 
"booking not found".

The /forms page must use the SERVICE ROLE 
key to fetch the booking, NOT the anon key.

In the forms API endpoint or forms page 
fetch, make sure it uses supabaseAdmin 
(service role) not supabase (anon):

  // WRONG — anon key, blocked by RLS:
  const { data } = await supabase
    .from('bookings')
    .select('*')
    .eq('id', bookingId)
  
  // CORRECT — service role, bypasses RLS:
  const { data } = await supabaseAdmin
    .from('bookings')
    .select('*')
    .eq('id', bookingId)

Also the /confirmed page fetch must use 
supabaseAdmin for the same reason.

=== 3. GDPR + DATA PRIVACY ===

a) Sensitive data handling:
   - Medical forms: encrypted at rest? At minimum RLS-locked (now yes)
   - Consent signatures: immutable once submitted?
   - Client PII: accessible only to admin, only the current admin's location
   - Payment data: only Stripe IDs stored locally, never card numbers

b) Data subject rights:
   - Can Eva delete all data for a specific client on request? (right to erasure)
   - Is there an export flow for "give me all my data"? (subject access request)
   - If missing, flag as high priority for future

c) Retention:
   - Are old bookings / forms kept forever? Any auto-delete after X years?
   - Document current retention (even if "infinite") so Eva knows

d) Cookie / tracking consent:
   - Public site: any analytics, pixels, cookies that need GDPR consent banner?
   - If using Stripe, Google Fonts, Google Maps, etc., document required disclosures

e) Privacy policy + T&Cs:
   - Linked in footer? Forms checkbox requiring acceptance?
   - Mention of how data is handled?

=== 4. SECURITY ===

a) Authentication:
   - JWT secret: from env var, not hardcoded? Sufficient length (32+ chars)?
   - JWT expiry: reasonable? (e.g. 24h for admin)
   - Logout invalidates token server-side OR clears client storage at minimum

b) Secrets:
   - All keys in Replit Secrets, not committed to git
   - No secrets in console.log anywhere
   - Stripe webhook signature verification enabled (CONFIRM THIS — critical)
   - Google OAuth client secret not leaked in any URL / logs

c) Input validation:
   - All POST endpoints type-check + length-limit fields
   - Email / phone / UUID format validated where expected
   - No SQL injection vectors (Supabase params handles most)
   - XSS: any .innerHTML with user data? Escape properly?

d) Rate limiting:
   - Login, enquiries, forms, public booking endpoints — all limited
   - Stripe webhook unlimited (retries expected)

e) Access control:
   - Every admin endpoint checks JWT
   - X-Location-Id header validated against current admin's allowed locations
   - Can admin from Location A access bookings from Location B via URL manipulation? (IDOR check)

f) Dependency check:
   - npm audit on api-server and frontend
   - Report high + critical vulnerabilities

g) File upload safety:
   - Media bucket restricted to images + video MIME types
   - File size limits enforced
   - No path traversal in filenames
